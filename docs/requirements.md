# 요구사항 정의서 — 인증 & 인사 (MVP)

> **범위**: 관리자 권한 기반 계정 관리 + 로그인 인증 + 인사
> **일정**: 2주 (설계 → 문서화 → 개발 → 배포 → 검증)
> **상태**: Confirmed

---

## 권한(Role) 정의

| 역할 | 코드 | 권한 범위 |
|------|------|----------|
| 관리자 | ADMIN | 전체 데이터 관리, 계정/조직 코드 관리, 시스템 설정 |
| 일반 사용자 | USER | 본인 인사정보 조회, 본인 계정 관리 |

> **접근 권한 표기**: 전체(미인증 포함) · 로그인 사용자(역할 무관) · 관리자 · 본인 · 시스템(자동)

---

## 1. 인증 (Authentication)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| AUTH-1 | 로그인 | ID/PW 인증 후 서버 세션 생성, 세션 쿠키(HttpOnly) 발급. 비활성(is_active=false) 계정은 로그인 거부 | 전체 | P0 |
| AUTH-2 | 로그아웃 | 서버 세션 무효화 + 세션 쿠키 삭제 | 로그인 사용자 | P0 |
| AUTH-3 | 세션 만료 | 사용자 미동작 1시간(idle timeout) 경과 시 세션 자동 만료 → 자동 로그아웃 처리 후 로그인 페이지로 이동. 로그인 후 최대 8시간 경과 시 절대 만료(absolute timeout) 후 재인증 요구 | 시스템(자동) | P0 |

## 2. 인가 (Authorization)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| RBAC-1 | 권한 제어 | 세션 기반 현재 사용자 식별 후 역할 기반 라우트·API 접근 가드 (관리자/일반), 미인증 401·권한부족 403 처리 | 시스템(자동) | P0 |
| RBAC-2 | 본인 자원 소유권 검증 | 일반 사용자는 자신의 인사정보·계정 자원에만 접근 가능하도록 본인 스코프 강제 (타인 자원 요청 차단) | 시스템(자동) | P0 |

---

## 3. 계정·자격증명 관리 (Account Management)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| ACCT-1 | 계정 생성 | 직원 등록(HR-5) 시 로그인 계정 자동 생성 — 로그인 ID(사번)·자동 생성 임시 비밀번호·역할 지정, 비밀번호 해싱 저장 | 관리자 | P0 |
| ACCT-2 | 로그인 ID 정책 | 로그인 식별자는 **사번**을 사용하며, 직원 등록 시 시스템이 자동 채번(입사연도+순번, 예: 2026-0001)하여 시스템 전체 유일성 보장 | 관리자 | P0 |
| ACCT-3 | 역할 변경 | 관리자가 기존 계정의 역할 변경 (일반 ↔ 관리자) | 관리자 | P1 |
| ACCT-4 | 계정 비활성화 | 계정 비활성화(is_active=false)로 로그인 차단, 인사 이력 보존 | 관리자 | P0 |
| ACCT-5 | 계정 재활성화 | 관리자에 의해 일시 비활성화된 계정을 다시 활성화. 단, 퇴사 처리로 비활성화된 계정은 복직 불가 정책(HR-7)에 따라 재활성화 대상에서 제외 | 관리자 | P1 |
| ACCT-6 | 비밀번호 변경 | 본인 비밀번호 변경 (bcrypt 단방향 해싱 저장) | 본인 | P1 |
| ACCT-7 | 비밀번호 초기화 | 사용자 비밀번호 분실 시 관리자 요청에 따라 시스템이 자동 생성한 임시 비밀번호로 재설정 | 관리자 | P1 |
| ACCT-8 | 초기 관리자 시드 | 시스템 최초 배포 시 환경변수/시드 데이터로 관리자 계정 1개 자동 생성 (부트스트랩) | 시스템(자동) | P0 |

## 4. 인사 (HR)

### 4-1. 부서·직급 공통 코드

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| HR-1 | 코드 등록 | 부서/직급 공통 코드 등록 (관리자 지정 코드값·명칭·유형). 동일 유형 내 코드값 중복 차단 | 관리자 | P0 |
| HR-2 | 코드 수정 | 코드 명칭 수정 (코드값은 등록 후 불변) | 관리자 | P1 |
| HR-3 | 코드 삭제 | 코드 삭제. 해당 코드를 참조하는 직원이 있으면 삭제 차단(참조 무결성) | 관리자 | P0 |
| HR-4 | 코드 목록 조회 | 부서/직급 코드 목록 조회 (직원 등록·수정 폼의 선택 소스) | 관리자 | P0 |

### 4-2. 직원 정보 관리

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| HR-5 | 직원 등록 | 인사 프로필 등록 + 로그인 계정 자동 생성(ACCT-1). 필수값·형식 검증, 부서·직급은 코드(HR-4)에서 선택 | 관리자 | P0 |
| HR-6 | 직원 정보 수정 | 등록된 직원 인사정보 수정 (사번은 불변, 부서·직급은 코드에서 선택) | 관리자 | P0 |
| HR-7 | 재직 상태 관리 | 퇴사 처리(재직→퇴사). 퇴사 시 계정 비활성화(ACCT-4) 연동, 인사 이력 보존. 퇴사는 비가역 상태로 복직(재활성화) 불가 | 관리자 | P1 |

### 4-3. 직원 조회

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| HR-8 | 직원 목록 조회 | 전체 직원 목록 조회 (무한 스크롤 — 최초 20건 로드, 목록 하단 도달 시 다음 20건 점진 로드) | 관리자 | P0 |
| HR-9 | 직원 검색·필터 | 이름·사번·부서·재직상태 기준 검색/필터 | 관리자 | P1 |
| HR-10 | 직원 상세 조회 | 개별 직원 인사정보 상세 조회 | 관리자 | P0 |
| HR-11 | 내 인사정보 조회 | 본인 기본 인사정보 조회 (읽기 전용, 수정 불가) | 본인 | P0 |

> **목록 표시 정책 (공통)**: 관리자 목록 화면(직원 관리·계정 관리·공통 코드)은 페이지 번호 방식 대신 **무한 스크롤**로 표시한다. 최초 진입 시 20건을 로드하고, 스크롤이 목록 하단에 도달하면 다음 20건을 이어서 로드한다. (공통 코드는 전체를 받아 클라이언트에서 20건 단위로 점진 노출)
