# 요구사항 정의서 — 인증 · 인사 · 근태 · 휴가 (MVP)

> **범위**: 관리자 권한 기반 계정 관리 + 로그인 인증 + 인사 + 근태·휴가(전자결재 기반 · 연차 자동 적립)
> **일정**: 2주 (설계 → 문서화 → 개발 → 배포 → 검증)
> **상태**: Confirmed
> **시각 기준**: 모든 시각·날짜·일(日) 경계 판정은 KST(Asia/Seoul) 기준이다. 저장은 UTC(timestamptz)로 하되 출퇴근·근태판정·만근·연차 적립·세션 만료 등 모든 판정과 표시는 KST로 변환한다.

---

## 권한(Role) 정의

| 역할 | 코드 | 권한 범위 |
|------|------|----------|
| 전사 관리자 | ADMIN | 전체 데이터 관리, 계정/조직 코드 관리, 시스템 설정, 전 직원 대상 조회·결재 |
| 부서 관리자 | MANAGER | 특정 부서의 팀장 직급 직원에게 부여. 일반 사용자 권한 + 같은 부서원의 근태·휴가 현황 조회 + 같은 부서원이 올린 근태 보정·휴가 결재의 승인·반려. 직원·계정·코드 등 전사 관리 기능은 없음 |
| 일반 사용자 | USER | 본인 인사정보·근태·휴가 조회 및 신청, 본인 계정 관리 |

> **3단계 권한 계층**: 전사 관리자(ADMIN) > 부서 관리자(MANAGER, 팀장) > 일반 사용자(USER). 부서 관리자는 특정 부서의 팀장 직급 직원에게 부여되며, 같은 부서원의 근태·휴가 현황을 조회하고 같은 부서원이 올린 결재의 승인자가 된다(RBAC-3 · 6. 결재 참조). 전사 관리 기능(직원·계정·코드·휴가 종류·공휴일·연차 잔액)은 전사 관리자만 수행한다.

> **접근 권한 표기**: 전체(미인증 포함) · 로그인 사용자(역할 무관) · 관리자(전사 관리자 ADMIN) · 부서 관리자(MANAGER) · 승인자(결재에 지정된 부서 관리자) · 본인 · 시스템(자동)

### 역할별 메뉴·기능 맵

**전사 관리자(ADMIN) 전용 메뉴 — 진입 화면별 조정 항목**

| 메뉴(화면) | 조정 가능 항목 | 관련 요구사항 |
|-----------|--------------|--------------|
| 직원 관리 | 직원 등록·정보 수정·퇴사 처리, 목록·검색·상세 조회 | HR-5~10 |
| 계정 관리 | 역할 변경(USER↔MANAGER↔ADMIN)·계정 활성/비활성·비밀번호 초기화 | ACCT-3·4·5·7 |
| 공통 코드 | 부서·직급 코드 등록·수정·삭제 | HR-1~4 |
| 휴가 종류 관리 | 휴가 종류 등록·수정·삭제 + 종류별 속성(유급·연차차감·증빙·한도 일수) 설정 | LEAVE-1 |
| 공휴일 관리 | 회사 공휴일·휴무일 등록·삭제 | ATT-11 |
| 연차 잔액 관리 | 직원별 연차 잔액 조회·수동 조정 | LEAVE-5 |
| 전체 근태 | 전 직원 근태 조회·검색·집계 | ATT-5·6·10 |
| 전체 휴가 | 전 직원 휴가 신청 조회 | LEAVE-9 |

**부서 관리자(MANAGER) 메뉴**: 결재함(APPR-2~4) · 부서 근태/휴가 현황·연차 적립 결과 조회(ATT-13·LEAVE-12·13) + 아래 일반 사용자 메뉴.

**일반 사용자(USER) 메뉴**: 내 인사정보(HR-11) · 출퇴근·내 근태(ATT-1·2·4) · 휴가 신청·내 휴가(LEAVE-6·7·8·12) · 내 결재 요청 현황(APPR-5) · 비밀번호 변경(ACCT-6).

## 1. 인증 (Authentication)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| AUTH-1 | 로그인 | ID/PW 인증 후 서버 세션 생성, 세션 쿠키(HttpOnly) 발급. 비활성(is_active=false) 계정은 로그인 거부. 반복 로그인 실패에 대한 시도 제한은 Supabase Auth rate limit 정책을 따르며, 제한 발생 시(일정 횟수 실패 시 일시 차단) 안내를 로그인 화면에 표시 | 전체 | P0 |
| AUTH-2 | 로그아웃 | 서버 세션 무효화 + 세션 쿠키 삭제 | 로그인 사용자 | P0 |
| AUTH-3 | 세션 만료 | 사용자 미동작 1시간(idle timeout) 경과 시 세션 자동 만료 → 자동 로그아웃 처리 후 로그인 페이지로 이동. 로그인 후 최대 8시간 경과 시 절대 만료(absolute timeout) 후 재인증 요구. 다기기 동시 세션 허용 여부는 Supabase Auth 세션 정책을 따른다 | 시스템(자동) | P0 |

## 2. 인가 (Authorization)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| RBAC-1 | 권한 제어 | 세션 기반 현재 사용자 식별 후 역할 기반 라우트·API 접근 가드 (관리자/일반), 미인증 401·권한부족 403 처리 | 시스템(자동) | P0 |
| RBAC-2 | 본인 자원 소유권 검증 | 일반 사용자는 자신의 인사정보·계정 자원에만 접근 가능하도록 본인 스코프 강제 (타인 자원 요청 차단) | 시스템(자동) | P0 |
| RBAC-3 | 부서 스코프 결재 권한 | 부서 관리자(MANAGER)는 같은 부서원의 근태·휴가 현황을 조회할 수 있고, 같은 부서원이 올린 결재 요청(근태 보정·휴가)을 승인할 수 있으며, 승인에 따라 해당 부서원의 근태 기록·휴가 잔액 자원을 수정할 수 있다. 전사 관리 기능은 전사 관리자(ADMIN)만 수행 | 시스템(자동) | P1 |
| RBAC-4 | 감사 로그 | 역할 변경·계정 활성/비활성·결재 승인/반려·연차 수동 조정·근태 보정 등 주요 변경의 행위자·시각·대상·변경 내용을 이력으로 기록·보존 | 시스템(자동) | P1 |

## 3. 계정·자격증명 관리 (Account Management)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| ACCT-1 | 계정 생성 | 직원 등록(HR-5) 시 로그인 계정 자동 생성 — 로그인 ID(사번)·자동 생성 임시 비밀번호·역할 지정, 비밀번호 해싱 저장 | 관리자 | P0 |
| ACCT-2 | 로그인 ID 정책 | 로그인 식별자는 **사번**을 사용하며, 직원 등록 시 시스템이 자동 채번(입사연도+순번, 예: 2026-0001)하여 시스템 전체 유일성 보장 | 관리자 | P0 |
| ACCT-3 | 역할 변경 | 전사 관리자가 계정의 역할을 3단계(일반 USER ↔ 부서 관리자 MANAGER ↔ 전사 관리자 ADMIN) 간에 변경. 단, 마지막 전사 관리자(ADMIN)는 다른 역할로 변경할 수 없다(전사 관리자 0명 방지) | 관리자 | P1 |
| ACCT-4 | 계정 비활성화 | 계정 비활성화(is_active=false)로 로그인 차단, 인사 이력 보존. 마지막 활성 전사 관리자(ADMIN)는 비활성화할 수 없다 | 관리자 | P0 |
| ACCT-5 | 계정 재활성화 | 관리자에 의해 일시 비활성화된 계정을 다시 활성화. 단, 퇴사 처리로 비활성화된 계정은 복직 불가 정책(HR-7)에 따라 재활성화 대상에서 제외 | 관리자 | P1 |
| ACCT-6 | 비밀번호 변경 | 본인 비밀번호 변경 (bcrypt 단방향 해싱 저장). 비밀번호 복잡도는 Supabase Auth 정책을 따르며, 적용 규칙을 비밀번호 입력·변경 UI에 안내 | 본인 | P1 |
| ACCT-7 | 비밀번호 초기화 | 사용자 비밀번호 분실 시 관리자 요청에 따라 시스템이 자동 생성한 임시 비밀번호로 재설정 | 관리자 | P1 |
| ACCT-8 | 초기 관리자 시드 | 시스템 최초 배포 시 환경변수/시드 데이터로 관리자 계정 1개 자동 생성 (부트스트랩) | 시스템(자동) | P0 |

## 4. 인사 (HR)

### 4-1. 부서·직급 공통 코드

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| HR-1 | 코드 등록 | 부서/직급 공통 코드 등록 (관리자 지정 코드값·명칭·유형). 동일 유형 내 코드값 중복 차단 | 관리자 | P0 |
| HR-2 | 코드 수정 | 코드 명칭 수정 (코드값은 등록 후 불변) | 관리자 | P1 |
| HR-3 | 코드 삭제 | 코드 삭제. 해당 코드를 참조하는 직원이 있으면 삭제 차단(참조 무결성) | 관리자 | P0 |
| HR-4 | 코드 목록 조회 | 부서/직급 코드 목록 조회 (직원 등록·수정 폼의 선택 소스) | 관리자 | P0 |

### 4-2. 직원 정보 관리

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| HR-5 | 직원 등록 | 인사 프로필 등록 + 로그인 계정 자동 생성(ACCT-1). 필수값·형식 검증, 부서·직급은 코드(HR-4)에서 선택. 등록 시 연차 잔액 레코드를 초기화하고 입사일 기준 자동 적립(LEAVE-3·4) 스케줄을 시작 | 관리자 | P0 |
| HR-6 | 직원 정보 수정 | 등록된 직원 인사정보 수정 (사번은 불변, 부서·직급은 코드에서 선택). 부서 이동 시 결재선(APPR-1)은 이후 신규 결재부터 새 부서 기준으로 적용되며, 진행 중인 대기 결재는 기존 지정 승인자가 그대로 처리한다 | 관리자 | P0 |
| HR-7 | 재직 상태 관리 | 퇴사 처리(재직→퇴사). 퇴사 시 계정 비활성화(ACCT-4) 연동, 인사 이력 보존. 퇴사 시 본인이 올린 대기 결재·휴가 신청은 자동 취소되고, 본인이 승인자인 대기 결재는 재배정(APPR-6)된다. 퇴사는 비가역 상태로 복직(재활성화) 불가 | 관리자 | P1 |

| HR-11 | 내 인사정보 조회 | 본인 기본 인사정보 조회 (읽기 전용, 수정 불가) | 본인 | P0 |

## 5. 근태 (Attendance)

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| ATT-1 | 출근 기록 | 본인이 출근 버튼 클릭 시 서버 시각으로 자동 기록(당일 1회). 동일 일자 중복 출근 차단. 기록 시각의 수정은 보정 결재(ATT-7)로만 가능 | 본인 | P0 |
| ATT-2 | 퇴근 기록 | 본인이 퇴근 버튼 클릭 시 서버 시각으로 자동 기록. 출근 기록 없으면 차단, 퇴근 ≥ 출근 검증. 기록 시각의 수정은 보정 결재(ATT-7)로만 가능 | 본인 | P0 |
| ATT-3 | 근태 상태 자동 판정 | 표준 근무시간(09:00~18:00, 휴게 1시간 제외 소정근로 8시간) 기준 자동 분류 — 09:00을 1분이라도 초과한 출근은 지각, 18:00 이전 퇴근은 조퇴, 미출근은 결근, 출근 후 미퇴근은 퇴근누락(유예시간 없음). 실근무시간(분) 집계. 반차 사용일은 근무 의무 반일 기준으로 판정한다 — 오전 반차는 13:00 기준(초과 출근 지각·18:00 이전 퇴근 조퇴), 오후 반차는 09:00 기준(초과 출근 지각·12:00 이전 퇴근 조퇴) | 시스템(자동) | P0 |
| ATT-4 | 내 근태 조회 | 본인 출퇴근·상태·근무시간 기간별 조회 (읽기 전용) | 본인 | P0 |
| ATT-5 | 전체 근태 조회 | 전 직원 근태 목록 조회 (무한 스크롤 — 20건 점진 로드) | 관리자 | P0 |
| ATT-6 | 근태 검색·필터 | 이름·사번·일자(기간)·근태상태 기준 검색/필터 | 관리자 | P1 |
| ATT-7 | 근태 보정 요청 | 본인이 기존 근태 기록을 선택해 보정값(출퇴근 시각·상태)·사유·승인자(같은 부서의 부서 관리자)를 지정하여 결재 요청 제출 → 승인자 결재함에 등록 (APPR-1 연동). 동일 근태 기록에 대기 중 보정 요청이 있으면 중복 제출 차단 | 본인 | P1 |
| ATT-8 | 보정 요청 취소 | 본인이 승인 전 보정 요청 취소 | 본인 | P1 |
| ATT-9 | 보정 승인 시 근태 자동 반영 | 보정 요청 승인(APPR-3) 시 대상 근태 기록을 보정값으로 즉시 수정. 트리거로 원자 처리 | 시스템(자동) | P1 |
| ATT-10 | 근무시간 집계 | 일/월 단위 근무시간·근태상태 통계 요약 | 관리자 | P1 |

## 6. 결재 (Approval)

근태 보정(ATT-7~9)과 휴가 신청(LEAVE-6)이 공유하는 공통 전자결재 기능. 신청자가 지정한 승인자(같은 부서의 부서 관리자 MANAGER)의 결재함을 통해 승인/반려된다.

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 개발 우선순위 |
|-----------|-----------|------|----------|--------------|
| APPR-1 | 승인자 지정 | 신청 시 같은 부서의 부서 관리자(MANAGER, 본인 제외) 중 1명을 승인자로 지정. 동일 부서에 부서 관리자가 없으면 전사 관리자(ADMIN)로 후보 확대, 그래도 없으면 신청 불가 안내 | 본인 | P1 |
| APPR-2 | 결재함 조회 | 승인자가 본인에게 배정된 대기 결재(근태 보정·휴가) 목록 조회 (무한 스크롤) | 승인자 | P1 |
| APPR-3 | 결재 승인 | 대기 결재를 승인. 근태 보정은 승인 시 대상 근태 기록에 반영(ATT-9). 휴가는 신청 시 이미 잔액이 차감(LEAVE-10)되어 있으므로 승인 시 확정 처리 및 휴가-근태 연동(LEAVE-11)만 수행한다 | 승인자 | P1 |
| APPR-4 | 결재 반려 | 대기 결재를 반려(반려 사유 기록). 휴가는 신청 시 차감된 잔액을 복원(LEAVE-10)하고 상태 종결하며, 근태 보정은 대상 기록 변경 없이 종결 | 승인자 | P1 |
| APPR-5 | 내 결재 요청 현황 | 신청자가 본인이 올린 요청의 상태(대기/승인/반려/취소)와 처리 결과 조회. 반려된 요청은 수정하여 재신청 가능 | 본인 | P1 |
| APPR-6 | 승인자 재배정 | 지정 승인자가 퇴사·비활성·부재로 결재를 처리할 수 없을 때 같은 부서의 다른 부서 관리자(MANAGER)에게 재배정(없으면 전사 관리자 ADMIN으로 확대) | 본인·관리자 | P1 |
| APPR-7 | 결재 알림 | 승인자에게 대기 결재 건수를, 신청자에게 승인·반려·재배정 결과를 시스템 화면에 표시(미확인 표시 포함) | 시스템(자동) | P1 |

> **결재 상태 흐름**: `대기(pending) → 승인(approved) | 반려(rejected) | 취소(cancelled)`. 승인·반려·취소는 종결 상태로 되돌릴 수 없다. 취소는 신청자가 승인 전에 가능하다. 단, 휴가는 승인 후에도 휴가 시작일 이전이면 신청자가 취소할 수 있으며 차감 잔액은 자동 환원된다(LEAVE-7).

## 9. 휴가·공가 종류별 법정 증빙 기준

> 휴가 종류(LEAVE-1)별로 신청 승인 시 요구할 수 있는 **증빙의 법적 근거**를 정리한다. 증빙 의무 수준을 네 가지로 구분한다.
>
> - **L1 (법령 명시)**: 시행령·시행규칙에 증빙 서류·서식이 규정됨 → 회사가 해당 서류를 요구할 근거가 명확.
> - **L2 (사업주 재량·실무)**: 법은 유급·허용 의무만 정하고, 증빙은 사업주가 요구할 수 있거나 실무 관행으로 제출(소집통지서 등).
> - **L3 (회사 규정)**: 법정휴가가 아니어서 증빙 기준이 취업규칙·단체협약 소관.
> - **불요**: 청구만으로 부여되며 증빙 요구에 법적 근거가 없거나 부적절.

### 9-1. 법정휴가 (근로기준법·남녀고용평등법)

| 종류 | 법적 근거 | 유급 여부 | 증빙 의무 수준 | 구체 증빙 자료 |
|------|----------|----------|--------------|--------------|
| 연차유급휴가 | 근로기준법 제60조 | 유급 | 불요 | 없음(시기지정권, 사유·증빙 불요) |
| 출산전후휴가 | 근로기준법 제74조 | 유급(최초 60일, 다태아 75일) | L2 | 출산 예정일·출산 사실 진단서(실무) |
| 유산·사산휴가 | 근로기준법 제74조·시행령 제43조 | 유급(임신주수별 10~90일) | L1 | 유산·사산 사실과 임신주수가 기재된 의료기관 진단서 |
| 생리휴가 | 근로기준법 제73조 | 무급 | 불요 | 청구만으로 부여, 진단서 요구 법적 근거 없음(입증책임은 사업주) |
| 배우자 출산휴가 | 남녀고용평등법 제18조의2 | 유급(20일, 2025.2.23~) | L2 | 출생 사실 증명(가족관계증명서 등, 실무) |
| 난임치료휴가 | 남녀고용평등법 제18조의3 | 최초 2일 유급(연 6일, 2025.2.23~) | L1 | 의료기관이 작성하고 난임치료 예정일이 명기된 증명서류 |
| 가족돌봄휴가 | 남녀고용평등법 제22조의2 | 무급(연 10일) | L2(약) | 법정 기재항목 신청서. 별도 증빙은 법령 미규정(사업주 요구 근거 제한적) |
| 육아휴직 | 남녀고용평등법 제19조 | 무급(고용보험 급여) | L2 | 자녀 정보 기재 신청서(주민등록등본 등 실무) |

### 9-2. 공가 (병역·공민권)

| 종류 | 법적 근거 | 유급 여부 | 증빙 의무 수준 | 구체 증빙 자료 |
|------|----------|----------|--------------|--------------|
| 예비군훈련 | 예비군법 제10조·근로기준법 제10조 | 유급(불이익 처우 금지·벌칙) | L2 | 훈련 소집통지서, 참석(이수)확인서 |
| 민방위훈련 | 민방위기본법 제27조 | 유급(불이익 처우 금지) | L2 | 소집통지서, 참석확인서 |
| 병역판정검사 | 병역법·근로기준법 제10조(공의 직무) | 시간 보장(유급 법정 강제 아님) | L2 | 병역판정검사 통지서 |
| 선거 투표 | 공직선거법 제6조·근로기준법 제10조 | 유급(투표시간 보장·불이익 금지) | 불요 | 없음(별도 증빙 불요) |
| 공의 직무(증인·배심원 출석 등) | 근로기준법 제10조 | 시간 보장(유급 법정 강제 아님) | L2 | 법원 출석요구서·소환장 등 |

### 9-3. 회사 약정휴가 및 산재

| 종류 | 법적 근거 | 유급 여부 | 증빙 의무 수준 | 구체 증빙 자료 |
|------|----------|----------|--------------|--------------|
| 경조사휴가 | 법정 근거 없음(취업규칙·단협) | 회사 규정 | L3 | 청첩장, 가족관계증명서, 사망진단서 등(회사 규정) |
| 병가(업무 외 질병·부상) | 법정 근거 없음(취업규칙) | 회사 규정 | L3 | 진단서·소견서(회사 규정) |
| 업무상 재해 요양 | 산업재해보상보험법 제40조·제52조 | 휴업급여(평균임금 70%, 근로복지공단) | L1 | 요양급여신청서 + 의학적 소견(공단 승인) |

> **요약**: ① 증빙 서류·서식이 **법령에 명시(L1)** 된 것은 유산·사산휴가·난임치료휴가·산재 요양 등 일부다. ② 예비군·민방위·출산휴가 등 다수 법정휴가·공가는 법이 **유급·허용만 강제**하고 증빙은 사업주가 요구하는 수준(**L2**)이다. ③ **경조사·병가는 법정휴가가 아니어서**(L3) 증빙 기준 자체가 회사 취업규칙 소관이다. ④ 연차·생리휴가는 **청구만으로 부여**되며 증빙 요구에 법적 근거가 없다(생리휴가는 입증책임이 사업주에게 있음).

### 9-4. 회사 증빙 정책 (본 시스템 적용 기준)

L1(법정 증빙 의무)을 제외하면 증빙 요구는 회사 재량이므로, 본 시스템은 다음 정책을 적용한다. 아래 증빙 필요 여부는 **권장 기본값**이며, 휴가 종류(LEAVE-1) 등록 시 관리자가 조정한다.

**기준(이분법)**: 본인 재량으로 쓰는 휴가는 증빙 불요, 외부 사건을 사유로 하는 휴가는 증빙 필수.

| 증빙 정책 | 휴가 종류 |
|----------|----------|
| **불요** | 연차·반차, 생리휴가(법상 요구 불가), 가족돌봄휴가, 선거 투표 |
| **필수**(기본값) | 출산전후·유산사산·배우자출산·난임치료·육아, 예비군·민방위·병역판정검사·공의 직무, 경조사, 병가, 산재 요양 |

**운영 원칙**

1. **선언**: 휴가 종류(LEAVE-1)마다 `증빙 필요 여부`·`증빙 안내 문구`를 관리자가 설정한다(위 표는 권장 기본값).
2. **강제**: `증빙 필요 = 참`이면 휴가 신청(LEAVE-6) 시 증빙 파일 1건 첨부가 필수이며, 미첨부 시 제출이 차단된다.
3. **확인·접근통제**: 첨부의 진위·적정성은 승인자가 결재함(APPR-2)에서 미리보기로 확인 후 승인(APPR-3)한다. 시스템은 첨부 존재 여부만 검증한다(자동 서류검증 없음). 증빙 파일은 신청자 본인과 지정 결재자만 열람할 수 있으며, 그 외(전사 관리자 포함)는 접근이 차단된다(진단서 등 민감정보 보호).
4. **첨부 제약·보관**: 허용 형식은 PDF·이미지(JPG/PNG)이며 최대 10MB. 증빙 파일은 근로기준법상 인사 관련 서류 보존 기준에 따라 퇴사 후 3년간 보관한 뒤 파기한다.

> **범위 한정**: 증빙은 1건 단일 첨부로 한정한다. 다중 파일, 사후 2단계 증빙(예: 예비군 참석확인서), 일수 조건부 증빙(예: 병가 N일 이상만 진단서)은 본 버전 범위에서 제외하며 향후 확장 과제로 둔다.

### 9-5. 휴가 종류별 일수 한도

법정 휴가는 법정 일수를, 법정 근거가 없는 휴가(경조사·병가)는 회사 정책 일수를 적용한다(LEAVE-1의 `한도 일수` 시드값으로, 관리자가 조정 가능).

**법정 일수**

| 종류 | 한도 일수 | 근거 |
|------|----------|------|
| 연차유급휴가 | 1년 미만: 월 1일(최대 11일) / 1년 이상: 15일(근속 가산) | 근로기준법 제60조 (LEAVE-3·4) |
| 출산전후휴가 | 90일(다태아 120일, 미숙아 100일) | 근로기준법 제74조 |
| 유산·사산휴가 | 임신주수별 10~90일 | 근로기준법 제74조 |
| 배우자 출산휴가 | 20일 | 남녀고용평등법 제18조의2 |
| 난임치료휴가 | 연 6일 | 남녀고용평등법 제18조의3 |
| 가족돌봄휴가 | 연 10일 | 남녀고용평등법 제22조의2 |

|------|------|----------|
